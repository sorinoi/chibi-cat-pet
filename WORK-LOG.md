## How to test (for a new session)

The helper scripts used so far lived in a session scratchpad and are gone; rebuild them as needed:
- Dev with DevTools protocol: `npx electron-vite dev --remoteDebuggingPort 9223`. Production: `node_modules/electron/dist/electron.exe . --remote-debugging-port=9224` (after `npm run build`). Installed app: `"%LOCALAPPDATA%\Programs\desktop-pet\Desktop Pet.exe" --remote-debugging-port=9225`. Never leave a debug port open on the app the user keeps running.
- CDP client: Node's global WebSocket against http://127.0.0.1:<port>/json; `Runtime.evaluate` for page state, `Input.dispatchMouseEvent` for clicks/drags into the page only.
- Pages in CDP `/json`: `index.html` (pet), `settings.html`, `adopt.html`; pick the target by URL.
- Dev-only hook `window.__petDebug` (pet page): `state()`, `scene()` (clip, frame, facing), `dispatch(event)`, `playClip(name)`, `setUserIdle(bool)`, `mood()`, `wanderNow()`. Stripped from production builds. Call `setUserIdle(false)` first: if the user is away the pet falls asleep and tests go wrong.
- Window checks from PowerShell (read-only): `GetWindowRect`, `GetWindowLong(GWL_EXSTYLE)` (0x20 transparent = click-through on, 0x8 topmost), `GetLayeredWindowAttributes` (opacity). Call `SetProcessDpiAwarenessContext(-4)` first so sizes are physical pixels. Filter by process: the installed app ("Desktop Pet.exe") also has a window titled "Desktop Pet"; dev and the unpacked build run as electron.exe.
- Precise visuals: read the pet canvas through CDP (`getImageData` / `convertToBlob`) instead of screen captures, which are too slow for short frames.
- Menus: Electron popup menus are `Chrome_WidgetWin_1` windows with no title (not Win32 `#32768`); open with `window.petApi.showContextMenu()` via CDP, then PostMessage WM_KEYDOWN to that window only.
- Message boxes (e.g. "Adopt a new cat?"): `#32770` task dialog owned by electron.exe with real `Button` children; SendMessage BM_CLICK to the button by its text.
- Care test data: the engine reads pet.json only at startup, so write a test pet.json into %APPDATA%\desktop-pet-dev before launching ({version 1, name, species "cat", adoptedAt, needs {hunger, happiness}, updatedAt, counters}); move updatedAt back to simulate time closed. Delete it afterwards.
- Strokes: send the mouse moves from one CDP connection about 25 ms apart; one process per move is too slow to count as a stroke.
- Startup timing: performance mark `pet:first-frame` vs the process StartTime.
- Isolated test runs (do not disturb the user's own dev run or data): the app appends `-dev` to userData when unpacked, so `--user-data-dir=<scratch>/ud` makes it use `<scratch>/ud-dev` and its own single-instance lock. Production build: `node_modules/electron/dist/electron.exe . --user-data-dir=<scratch>/ud --remote-debugging-port=9224 [--settings]`. Dev build with the debug hook: `npx electron-vite dev --remoteDebuggingPort 9223 -- --user-data-dir=<scratch>/ud`. Write pet.json/settings.json into `<scratch>/ud-dev` first. Stop it by its own PID tree only (match the command line; it may use forward slashes), then delete the folder.
- Falls (V5-M1): put the cat in the air with SetWindowPos on the test run's own window (find it by PID from the command line with the scratch user-data-dir; physical px = DIP x DPI/96), then `__petDebug.dispatch('dragStart')` and `dispatch('dragEnd')`: main follows the real cursor, so an unmoved mouse leaves the window in place and the drop falls. Sample `window.screenY` from CDP. A settings.json position in the air makes it fall at start.
- Perches (V5-M2): test windows from a PowerShell WinForms script (own process, topmost, titles "Perch A" and "Cover B"); run it with -STA and its own DoEvents loop (Application.Run returned early) and move the windows with SetWindowPos in physical px (their start Bounds came out wrong). In PowerShell pass [NullString]::Value, not $null, to FindWindowW. Do not make a big window topmost or maximize a topmost one: Windows then reports a busy/fullscreen state and FR-16 hides the pet mid-test. The user's real windows can be perches too (a terminal edge caught the cat once): start the cat just above the test edge.
- Perch riding (V5-M3): a perched cat snaps back to its edge, so a SetWindowPos lift is undone; lift it with Gravity off (settingsApi.update({ gravity: false }) from the settings page, no perch watch), move it, then Gravity on (settle drops it). Slide a test window smoothly with one process (a loop of SetWindowPos); pass negative numbers to a PowerShell -File script as named arguments (-dy -150), or they are read as parameter names. Maximize a test window only after making it not topmost. Per-check cost was measured with a temporary performance.now() log around inspectWindow (removed).
- Jumps (V5-M4): `__petDebug.jumpNow()` tries a jump now (no chance or cooldown) but only from idle; the real mouse near the cat puts it in look, so send `__petDebug.cursor({ x: -5000, y: -5000, width, height })` first. To hit the top of an arc (FR-74) use one Node script: CDP jumpNow, then koffi FindWindowW/ShowWindow on the test window after ~300 ms (the PowerShell start-up is too slow and uneven).
- Dev hook additions: `__petDebug.cursor({x, y, width, height})` feeds a cursor position as if main sent it (looking without moving the real mouse); `lookWatching()` says whether main is polling.
- pet.json now also has `treats` (0..5); focus.json is version 2 `{ version: 2, days: { "YYYY-MM-DD": count } }` (version 1 is upgraded). Settings keys added in v3/v4: language, focusMinutes, shortBreakMinutes, longBreakMinutes, longBreakEvery, autoStartBreaks, autoStartFocus, focusNotifications, hungerReminder, focusTreats.
- Cat right-click menu order (for keys posted to the app's own menu window): Feed, Pet, [Give a treat (N) when on and stocked], Focus > (status line, then the actions that apply: Start focus / Pause, Skip, Stop / Resume, Skip, Stop / Start break, Skip break, Stop), Hide, Settings, Quit.
